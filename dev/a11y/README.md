# a11y/ — the colour-contrast auditor

One engine, driven by `tests/W/run.sh` (`npm run test:a11y`).

It renders every Storm surface in real chromium against the vault's own shipped
`.obsidian/snippets/storm.css`, through the same Obsidian/Dataview harness the other
suites use, across the whole palette matrix — static dark, e-ink light, community
dark and light, the theme file the build ships, and five "Match image" palettes
produced by the REAL `_extract()` / `_buildTheme()` in `dashboard/helpers.js` fed
synthetic banner buffers. For every element with text it reads the computed colour and
the effective background behind it, and fails anything under 4.5:1 (normal text), 3:1
(large text), or 3:1 for the non-text boundaries that carry meaning — chart bars against
the chart ground, the today line, milestones, focus rings.

| file | what it is |
|---|---|
| `audit.js` | the runner: `node a11y/audit.js [--json FILE] [--shots] [--only KEY] [--vault NAME]` |
| `audit-surfaces.js` | which block renders in which note, and at what width — one entry per surface |
| `fixtures.js` | the vault it renders: the real built tree plus synthetic notes covering every colour-bearing state |
| `palettes.js` | the palette matrix, generated by the shipping code rather than re-implemented |
| `probe.js` | the in-page walker that resolves each element's effective background |
| `graphics.js` | the non-text boundaries that carry meaning, and their thresholds |
| `shots.js` | `node a11y/shots.js` → annotated before/after screenshots under `a11y/shots/` |

**Adding a surface.** A surface nobody lists in `audit-surfaces.js` is not audited at
all. Add it there, not to the runner. Suite W fails loudly when a surface does not
render, rather than scoring it zero — a silent zero is how an audit lies.

The pass that brought every surface to AA is summarised in `../../CHANGELOG.md` (2.0.0 →
Fixed) and in `../DEVLOG.md`; the guards that keep each fix in place are part 2 of
`tests/W/run.sh`.
